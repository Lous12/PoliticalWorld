# Political World 1.10.0-dev4

Development build focused on UI framework cleanup.

## Settlement Politics
- Political World no longer dumps the full local political model into the vanilla settlement stats list.
- The normal settlement page keeps only Settlement Stability and Dominant Ideology as at-a-glance rows.
- A dedicated Politics side-tab opens a full local Politics page with stability, ideology, tradition, government support, political division, ideological hostility, parties, central-government context and rebellion risk.
- The page uses the vanilla settlement window scroll host instead of opening a separate popup.

## PoliticalWorldAPI 1.16
- `UI.RegisterPoliticsPage(...)`
- `UI.RegisterKingdomPoliticsPage(...)`
- `UI.RegisterSettlementPoliticsPage(...)`
- Addons render into a host-owned page context instead of Harmony-patching private Political World UI methods.
- New capabilities: `ui.politics-pages`, `ui.kingdom-politics-pages`, `ui.settlement-politics-pages`, `sdk.1.16`.

## Compatibility
The previous inspector/context-action UI API remains available. Existing 1.15 calls are not removed.

## Testing note
This build still needs runtime validation in WorldBox 0.51.2, especially the settlement side-tab position and CityWindow scrollbar bridge on different UI scales.

## dev4 UI fix

- Settlement Politics now clones a real vanilla `WindowMetaTab`, just like Kingdom Politics.
- WorldBox owns the settlement Politics tab position, selected state, spacing and page visibility.
- The old screen-space overlay button remains only as a compatibility fallback.
- This fixes the Politics page visually laying over another settlement tab.

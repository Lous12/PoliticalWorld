# Что можно сделать с помощью Political World?

Political World — это и мод про политику, и платформа для аддонов.

Главное различие:

> **Сам Political World занимается политикой. PoliticalWorldAPI не обязан ограничивать ваши идеи только политикой.**

Текущая база репозитория: Political World **1.11.0**, PoliticalWorldAPI **1.19.0**.

## Что уже есть в Public API

API 1.19 предоставляет публичные поверхности для:

- идеологий и идеологических течений;
- своих форм правления и government archetypes;
- партий и правящей партии;
- политического состояния государства и стабильности;
- Event Bus и собственных событий аддона;
- Actions и Rare Events;
- Conditions и Effects;
- собственных данных и тегов аддона на Actor/City/Kingdom;
- необязательной локализации с читаемым fallback-текстом;
- ограниченных world queries и lifecycle-событий мира;
- ленивых миграций данных аддона;
- inspector UI и context actions;
- полноценных страниц в Politics UI государства и поселения;
- политических профилей рас и шаблонов динамических названий стран;
- warfare helpers;
- capability discovery, диагностики экосистемы и support report.

На этом уже можно нормально строить:

- наборы идеологий и форм правления;
- политические события;
- расширения партий и выборов;
- fantasy politics и альтернативную историю;
- инструменты для сценариев и разработчиков;
- городские/государственные метаданные;
- интеграции между несколькими аддонами;
- свои страницы внутри Politics UI;
- внешние системы, которые реагируют на события PW вместо постоянного сканирования мира.

## Чего это не означает

Наличие публичных примитивов не означает, что готовая игровая система уже существует в core.

Например, API может дать экономическому аддону данные, события, доступ к миру и UI-хост, но это не превращает Political World в готовый мод на экономику и торговлю.

Отдельные проекты могут быть про:

- религии и культы;
- магию;
- экономику и торговлю;
- болезни и эпидемии;
- технологии;
- профессии;
- RPG-механики персонажей;
- династии;
- образование и социальные системы;
- инструменты для других моддеров;
- связки из нескольких независимых аддонов.

## Начинайте с малого

Первый полезный проект может содержать:

- одно событие;
- одну идеологию;
- одну форму правления;
- один Action;
- одно своё значение в данных государства;
- один listener на событие другого аддона;
- одну inspector-секцию;
- один маленький инструмент.

Такие проекты легче понять, протестировать и закончить.

## Из чего лучше строить аддон

Здоровая схема примерно такая:

```text
Аддон
  ↓
регистрирует контент/capabilities
  ↓
хранит свои данные
  ↓
реагирует на lifecycle/core/addon events
  ↓
проверяет Conditions
  ↓
применяет Effects / Actions
  ↓
публикует события для других аддонов
```

А вот такой вариант лучше не делать без очень веской причины:

```text
Update()
  ↓
каждый кадр сканируем весь мир
  ↓
reflection в Main
  ↓
надеемся, что следующий релиз ничего не сломает
```

## Экосистема из нескольких аддонов

Не обязательно делать один огромный overhaul, который владеет всем.

```text
Мод на религии ─┐
Мод на магию ───┼─→ общие события / capabilities
Мод на экономику┤
Политический мод┘
```

Каждый проект может оставаться маленьким и отдавать наружу только нужные другим возможности.

## Зачем здесь Scenario Tools

Scenario Tools — first-party аддон и одновременно полигон для API.

Правило должно быть тем же, что и для сторонних аддонов: если полезную функцию нельзя нормально выразить через Public API, лучше расширить API, чем навсегда выдавать одному аддону приватный backdoor.

## Если Political World вообще не нужен

Нормально.

В репозитории есть отдельный starter для обычного NeoModLoader-мода и документация по NML UI. Political World не заменяет NeoModLoader — он даёт более высокий уровень инструментов там, где это действительно удобно.

## С чего начать

Если хотите сделать аддон поверх Political World:

1. Скопируйте `templates/PoliticalWorld-Addon-Template`.
2. Пройдите [быстрый старт](GETTING_STARTED.md).
3. Откройте [индекс `examples/`](../../examples/README.md) и возьмите самый маленький подходящий пример.
4. Прочитайте [справочник API 1.19](API_REFERENCE_1_19.md).
5. Сделайте одну видимую функцию.
6. Проверьте её в WorldBox и посмотрите `Player.log`.
7. Если Public API чего-то не умеет — предложите capability вместо доступа к внутренним классам.

Для полностью самостоятельного мода используйте `templates/WorldBox-NeoMod-Starter`.

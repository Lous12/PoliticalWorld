# Куда мы развиваем PoliticalWorldAPI

> **Political World не должен решать за автора, какой мод ему можно делать.**

Когда мы начали открывать API, он почти целиком был про политику. Это логично: сам Political World — политический мод, и первыми наружу вышли именно идеологии, партии, формы правления и события.

Но потом появилась простая мысль: если API уже умеет хранить данные аддонов, передавать события, проверять условия и запускать действия, зачем искусственно ограничивать всё это политикой?

Поэтому долгосрочная цель теперь шире: **PoliticalWorldAPI должен стать удобной платформой для разных аддонов поверх WorldBox и NeoModLoader.**

Сам Political World при этом никуда не исчезает и не превращается в «мод на всё». Политика остаётся нашей игровой системой. Просто другие авторы получают инструменты, чтобы строить поверх неё — или рядом с ней — свои собственные механики.

## Что мы не собираемся ломать

- Проект по-прежнему называется **Political World**.
- Публичная точка входа остаётся `Lous12.PoliticalWorld.PoliticalWorldAPI`.
- Старые аддоны ветки 1.x должны продолжать работать, насколько это возможно без поломки API.
- Политические функции остаются полноценной частью платформы.
- Производительность по-прежнему важнее «симуляции всего на каждом кадре».
- Наши собственные аддоны используют те же публичные возможности, что и аддоны сообщества.

## Что хотим добавить дальше

API не должен исходить из того, что каждый проект — обязательно ещё один политический пак.

Вместо этого мы хотим постепенно собрать набор общих инструментов:

```text
Core
├─ регистрация аддонов
├─ проверка возможностей API
├─ локализация и запасной текст
├─ хранение данных
├─ теги
├─ Event Bus
├─ Actions
├─ Conditions
├─ Effects
└─ диагностика

World
├─ государства
├─ города
├─ жители
├─ кланы
├─ культуры
├─ альянсы
└─ другие безопасно открытые объекты WorldBox

Content
├─ универсальные типы контента
├─ метаданные
├─ категории
├─ иконки
└─ реестры контента самих аддонов

UI
├─ дополнительные разделы инспектора
├─ действия в контекстном меню
├─ окна
└─ интеграция с инструментами вроде Scenario Tools

Politics
├─ идеологии
├─ правительства
├─ партии
├─ выборы
├─ кризисы
└─ блоки
```

Это не обещание конкретных названий методов. Архитектура ещё будет меняться. Важнее сам принцип: **политика — один из модулей API, а не его граница**.

## Аддоны должны уметь разговаривать друг с другом

Ещё одна важная цель — чтобы два независимых аддона могли взаимодействовать без жёсткой зависимости друг от друга.

Например, мод на магию сообщает:

```text
mymagic.storm_started
```

А дальше каждый желающий реагирует по-своему:

```text
Магический аддон
        ↓
    началась буря
        ↓
Религия: растёт вера
Экономика: падает торговля
Политика: снижается стабильность
```

Авторы этих аддонов могут вообще не работать вместе. Им достаточно договориться о событии или проверить доступную возможность другого аддона.

## Перевод не должен быть обязательным условием

Никто не должен переводить первый маленький аддон на все языки WorldBox только ради того, чтобы он нормально запустился.

Если перевода на язык игрока нет, API должен попробовать:

1. текст на текущем языке;
2. зарегистрированный текст по умолчанию;
3. английскую версию;
4. обычный `DisplayName` или `Description`;
5. в крайнем случае — понятный ID.

Переводы всё равно полезны и приветствуются. Просто их отсутствие не должно ломать аддон.

## Мы не хотим быть бутылочным горлышком

Мы физически не можем заранее добавить отдельный метод для каждой идеи:

- религий;
- заклинаний;
- технологий;
- болезней;
- профессий;
- преступности;
- образования;
- новых ресурсов;
- социальных систем;
- и всего, что люди ещё придумают.

Поэтому вместе с удобными готовыми функциями нужны **универсальные инструменты**, из которых автор сможет собрать собственную систему.

## Наши аддоны — проверка API на практике

Scenario Tools, Fantasy Politics и будущие first-party проекты не должны получать особый доступ к внутренностям Political World.

Если нам самим для нового аддона не хватает публичного метода, это не повод обойти API. Это отличный тест, который показывает, чего в API пока не хватает.

Именно так уже появилась возможность вручную запускать Rare Events и расширилась работа с партиями и локализацией.

## Что уже умеет API 1.9

У нас уже есть база:

- необязательная локализация с английским запасным текстом;
- метаданные аддонов;
- приватные данные и теги;
- Event Bus;
- Actions;
- Conditions;
- готовые Effects;
- диагностика;
- поиск и пакетная регистрация контента;
- понятные результаты операций вместо одного `true/false`.

При этом многие конкретные методы пока всё ещё завязаны на государства и политические системы. Это нормально: мы расширяем API постепенно и проверяем новые части на реальных аддонах.

## Следующий шаг

После 1.9 приоритет — не новые игровые механики в основном моде, а **General Framework**.

В первую очередь хотим развивать:

- данные и теги для разных объектов мира;
- безопасную работу с городами и жителями;
- универсальные реестры контента;
- собственные события аддонов и передачу данных через них;
- расширяемые Conditions и Effects;
- подключаемые элементы интерфейса;
- взаимодействие между аддонами;
- инструменты для сохранений и миграций данных;
- диагностику производительности.

Идея в итоге очень простая: **если кто-то хочет сделать через наше API мод на религии, магию или экономику, ему не нужно ждать, пока мы сами добавим всё это в Political World.**

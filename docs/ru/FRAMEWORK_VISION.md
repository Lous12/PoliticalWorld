# Видение фреймворка Political World

> **Political World не должен решать за автора, какой мод ему разрешено создавать.**

Political World начинался как политический мод. Поэтому и первый Public API в основном открывал политические системы — именно они уже существовали в проекте.

Но это больше не конечная цель.

Долгосрочная цель — универсальный фреймворк аддонов поверх WorldBox + NeoModLoader. Политика остаётся игровым содержимым самого Political World, а фреймворк даёт безопасные кирпичики, которые другие авторы смогут соединять так, как мы сами даже не предусмотрели.

## Что не меняется

- Мод остаётся **Political World**.
- Стабильная публичная точка входа остаётся `Lous12.PoliticalWorld.PoliticalWorldAPI`.
- Совместимость 1.x аддонов по возможности сохраняется.
- Политика остаётся полноценным модулем.
- Производительность остаётся event-driven и aggregate-first.
- First-party аддоны обязаны использовать те же публичные правила, что и моды сообщества.

## Что меняется

API постепенно должен перестать считать, что каждый аддон обязательно политический.

Нам нужны универсальные примитивы:

```text
Core
├─ addon registry
├─ capabilities
├─ localization + fallback
├─ data storage
├─ tags
├─ Event Bus
├─ Actions
├─ Conditions
├─ Effects
└─ diagnostics

World
├─ kingdoms
├─ cities
├─ actors
├─ clans
├─ cultures
├─ alliances
└─ другие безопасные объекты WorldBox

Content
├─ generic definitions
├─ metadata
├─ categories
├─ icons
└─ addon-owned registries

UI
├─ inspector sections
├─ context actions
├─ windows
└─ интеграция creator tools

Politics
├─ ideologies
├─ governments
├─ parties
├─ elections
├─ crises
└─ blocs
```

Точная форма методов может развиваться в рамках API 1.x, но направление уже определено.

## Аддоны должны уметь взаимодействовать

Независимые аддоны должны иметь возможность публиковать namespaced events и реагировать друг на друга без жёсткой зависимости.

Например:

```text
Magic addon
    публикует: mymagic.storm_started
            ↓
Religion addon реагирует
Economy addon реагирует
Political addon реагирует
```

Так экосистема сможет складываться из маленьких независимых проектов.

## Локализация должна быть необязательной

Автор не обязан переводить аддон на все языки WorldBox до первой публикации.

Правильный fallback:

1. перевод текущего языка;
2. зарегистрированная/default локализация;
3. английский fallback;
4. `DisplayName` / `Description`;
5. безопасный читаемый ID.

Перевод делает аддон лучше. Отсутствие перевода не должно делать его нерабочим.

## Мы не должны становиться бутылочным горлышком

Political World не сможет заранее сделать отдельные методы под каждую идею:

- religion;
- spell;
- technology;
- disease;
- profession;
- crime;
- education;
- custom resource;
- social system;
- и тысячи вещей, которые мы не можем предугадать.

Поэтому кроме удобных специализированных API нужны универсальные регистрация, данные и события.

## First-party аддоны — тест Public API

Scenario Tools, Fantasy Politics и другие наши аддоны не должны получать секретный доступ во внутренности.

Если через Public API невозможно сделать нужную функцию, это полезный сигнал:

> фреймворку не хватает capability.

Так API будет расти из реальных потребностей аддонов, а не из абстрактной сложности.

## Что уже есть в API 1.9

API 1.9 уже содержит универсальные части:

- необязательную локализацию и English fallback;
- addon metadata;
- namespaced data/tags;
- Event Bus;
- Actions;
- Conditions;
- готовые Effects;
- diagnostics;
- поиск/пакетную регистрацию контента;
- структурированные результаты операций.

При этом большинство конкретных world-state методов пока ещё привязано к политике и государствам.

## Следующий шаг: General Framework

Следующие версии API должны расширять именно универсальную платформу, а не игровой контент ядра.

Приоритетные направления:

- addon data/tags для разных объектов мира;
- безопасный доступ к городам и актёрам;
- generic content registries;
- пользовательские события и payloads;
- расширяемые Conditions и Effects;
- регистрация UI/inspector sections;
- обнаружение capabilities других аддонов;
- lifecycle и миграция сохранений;
- диагностика производительности.

Автор не должен ждать, пока Political World сам станет модом на религии, магию или экономику. Он должен получить инструменты и сделать это сам.

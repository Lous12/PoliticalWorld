# Куда мы развиваем PoliticalWorldAPI

> **Political World не должен решать за автора, какой мод ему можно делать.**

Political World начинался как политический мод, поэтому первые версии API закономерно были почти целиком про идеологии, партии, формы правления и события.

Более широкая цель — удобный набор безопасных инструментов для аддонов поверх WorldBox + NeoModLoader. Сам Political World при этом не превращается в «мод на всё»: политика остаётся его собственной игровой системой.

## Текущее состояние проекта

Political World 1.11 / API 1.19 — текущая база. Активная разработка больших новых функций сейчас на паузе.

Это не означает, что фреймворк заброшен. Сейчас важнее поддержка, критические фиксы, документация, понятные публичные границы и то, чтобы репозиторий был удобнее для форков, PR и авторов аддонов.

## Что остаётся

- Проект по-прежнему называется **Political World**.
- Публичная точка входа остаётся `Lous12.PoliticalWorld.PoliticalWorldAPI`.
- Аддоны ветки 1.x стараемся не ломать без причины.
- Политика остаётся полноценным модулем.
- Производительность важнее симуляции всего на каждом кадре.
- Наши аддоны должны жить по тем же публичным правилам, что и аддоны сообщества.

## Общее направление

API не должен исходить из того, что каждый новый проект обязательно политический. Важнее универсальные инструменты:

- регистрация аддонов;
- capability discovery;
- локализация и fallback;
- данные и теги;
- Event Bus;
- Actions / Conditions / Effects;
- диагностика;
- безопасный доступ к объектам мира;
- UI integration;
- контент, принадлежащий самому аддону.

## Аддоны должны разговаривать друг с другом

Независимые аддоны должны иметь возможность публиковать namespaced events и реагировать на них без жёстких зависимостей.

## Что уже умеет API 1.19

API 1.19 уже даёт регистрацию аддонов, локализацию, data/tags, события, actions, conditions/effects, диагностику, работу с идеологиями/правительствами/партиями, доступ к государствам, warfare helpers, UI integration, lifecycle helpers и другое.

Сейчас важнее нормально задокументировать и закрепить использование этой базы, чем делать вид, будто следующий шаг обязательно должен быть очередным огромным циклом механик в core.

## Если capability не хватает

Если community или first-party addon не может безопасно сделать что-то через Public API, это полезный сигнал. Лучше добавить/запросить небольшую публичную capability, чем завязывать проект на reflection во внутренности PW.
